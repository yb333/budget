# 数据模型讨论稿（v1.0 定稿 · 2026-11-20）

> 五轮问答完成，设计冻结，按此重构。最后补充的三个要点：①规划初期无编码，导入后手动关联；②授予流水做辅助手工记录；③规划 USD / 平台 CNY，汇率 7.03 可配置。

## 补充定稿（第五轮）

- **每月导入 4 个文件**：PO明细 ×2 + 执行表 ×2（每个花钱项目各一份）
- **OD 调拨选到预算来源** → 调拨建议细化到预算来源级（按各来源 IT外包剩余占比给分配表）
- **规划→平台关联**：年初录入 = 名称 + 美金金额（无编码）；平台数据出现新编码时看板提示关联（下拉选规划项），关联后按编码自动 join；名称不一致显示「平台名称（规划名称）」
- **授予流水**（辅助、可选）：手工记 日期+预算来源+金额CNY；与执行表「本年度授予」交叉校验
- **币种**：规划 USD，平台 CNY，汇率默认 7.03（meta.fxRate 可改）；执行率 = CNY执行 ÷ (USD规划 × 汇率)；展示双币种
- **以前年度授予未结算**不在规划分母内 → 执行率可能 >100%，属正常（超额完成）

## 其余章节见下（与 v1.0-rc 相同）

## 一、平台数据结构（定稿）

```
花钱项目（PO明细「IT项目名称」，×2；月度 OD 支出倾向只放一个项目）
  └─ 预算来源（考核维度；编码两边一致；约十几个；年中会调增调减/新增）
       └─ 费用类型：IT外包（PO，授予默认都进这里）｜ 人力外包(OD)（靠手工从 IT外包 调拨）
            ├─ 可用预算 = 以前年度授予未结算 + 本年度授予
            ├─ 1-上月执行（IT外包=PO实际执行；OD=滞后结算的扣减）
            ├─ 当月-12月预测（平台算，仅 IT外包；OD 预测由看板补位）
            └─ 剩余 = 可用 − 执行 − 预测（OD 组 = 可用 − 执行）＝可支配余额
```

- **PO明细表**：一行 = PO × 预算来源分摊；`N月执行`（过去）/`N月预测`（当月起）动态列头；OPEN/CLOSED；按年全量导出；费用起始时间 = PO 所属月；超出所属月的预测值 = 未花掉、验收后返还。
- **预算执行-项目表**：预算来源 × 费用类型两级表头快照；`-`合计行；无花钱项目标识列 → 批次合并。
- 自有人力：忽略（导入时跳过该列组；以后有钱再说）。

## 二、OD 结算机制（看板预测算法的核心依据）

- 常规月 M 月底：扣 M-1 月 OD 费用（滞后一个月）
- 6 月底：清算上半年（多扣）
- 12 月底：扣完全年 + 年终奖，**一次约 3~4 个月的量**（按 3~4 个月均值做默认，每年 11 月手工校准）
- OD 的预算来源分摊：只能事后从执行表 OD 组获取
- 预算授予全部进 IT外包；OD 可用额度来自用户手工调拨（倾向指定单一花钱项目负责当月 OD）

## 三、月度运营流程（定稿）

| 时点 | 动作 |
|---|---|
| 每月 18~19 号 | 导出 2 类文件（按年全量）→ 导入看板 → 看「下月 PO 建议」+「OD 调拨建议」 |
| 20 号左右 | 下下月 PO（可多张）、执行 OD 调拨 |
| 月底/次月初 | 再导一次 → 交叉校验对账、执行率定格、月度趋势存档 |
| 5 月中 / 11 月中 | 清算月预警：6 月/12 月 OD 大额扣减（含年终奖），提前建议调拨 |

数据导入频次 = 每月 2 次；导入 = 覆盖式刷新当年数据 + 执行表按导出日期存快照。

## 四、核心公式（定稿）

```
执行率（考核）   = (IT外包已执行 + OD已执行，截至上月) ÷ 年初规划总额   [分母手工录入，按预算来源]
预测执行率       = (已执行 + PO平台预测 + OD看板预测[滞后+清算+年终奖]) ÷ 年初规划
授予进度预警     = Σ可用预算 ÷ 年初规划  vs 时间进度（黄：落后10pt；催 BA）
下月 PO 建议     = 下月达标所需总消耗 − 已下PO在下月的预测 − OD下月预计扣减
OD 调拨建议      = 下月 OD 预计扣减（含清算月放大） − OD 当前可用额度
在途冻结         = OPEN PO 金额 − 已执行
预计返还         = OPEN PO 超出费用窗口的预测值（3月PO 4月验收，周期约1个月，要催）
交叉校验         = PO明细按预算来源汇总(≤上月) vs 执行表 IT外包 1-上月执行
```

## 五、年初规划与对齐

- 手工录入一次：预算来源编码 + 名称 + 计划金额（约十几个；给钱不区分花钱项目，统一看）
- 年中调整：调增调减/新增 → 看板支持编辑规划（V1 直接改金额，记录更新时间）
- 名称不一致（约半数）：按**编码**对齐；看板显示「平台名称（规划名称）」，不做别名引擎
- 编码是唯一 join key（PO明细「项目编码」= 执行表「预算来源编码」）

## 六、看板形态（定稿）

- 单用户、只读展示（不做分摊编辑——用户明确不想手调）、单文件 HTML 延续
- 每月文件导入：拖入 N 个文件自动识别类型（PO明细/执行表），执行表批次合并成带日期快照
- 年初一次：录入规划；导入后全自动计算
