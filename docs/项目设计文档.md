## 一、项目背景

### 是什么
一个**单文件 HTML 预算执行看板**，帮助预算负责人（用户）管理年度预算的执行、预测、达标。

### 核心用户
- **维护者**：预算负责人（唯一编辑者），负责花钱和管理执行率
- **查看者**：BA（预算申请）、团队成员（局域网只读）

### 核心诉求（按优先级）
1. **看进展和风险**：当前执行率、预计年底、授予进度、在途冻结
2. **知道怎么做**：下个月 PO 下多少、OD 调拨多少、分给哪些预算来源
3. **尽量无脑操作**：平台导出 Excel 丢进文件夹 → 打开看板 → 一切自动

### 约束
- **零部署**：不需要数据库、后端、云服务
- **Windows + Chrome**：内网环境，通过 git 仓库同步（只拉取不上传）
- **数据安全**：本地文件为唯一真源，清浏览器不丢数据

## 二、业务模型

### 三层结构

```
花钱项目（IT项目，×2）
  └─ 预算来源（考核维度，约十几个，可拆分到两个花钱项目）
       └─ 费用类型
            ├── IT外包（走 PO）
            ├── 人力外包 OD（按月扣减）
            └── 自有人力（不管理，导入时忽略）
```

### 预算来源的生命周期

```
年初规划（USD） → BA 申请 → 分笔授予（CNY） → 消耗（PO + OD） → 年底考核执行率
```

- **规划**：年初定，单位 **WUSD（万美金，保留小数）**，如 5.5 = $55,000
- **授予**：BA 申请后分笔到账，**全进 IT外包**；OD 用度需手工从 IT外包 调拨
- **考核**：执行率 = 已消耗 ÷ 规划×汇率；**每个来源有独立目标**（100%/92%/不考核/默认）
- **来源完全隔离**：A 的剩余不能给 B 补——B 缺钱要么催 BA（还没给），要么标失效（给不了了）

### PO（采购订单）

- **按自然月下达**：每月 20 号左右下下月 PO
- **冻结机制**：下单即冻结 → 执行中 → 验收（约 1 个月）→ 未花完的返还
- **跨年执行**：12 月服务的 PO 在次年 1 月下达，计入次年执行
- **挂靠 PO**：别人用你的预算额度下的 PO，不属于你的管理范围（可标记剔除）

### OD（按月扣减）

- **滞后结算**：M 月底扣 M-1 月的费用
- **年中清算**：6 月底清算上半年（多扣约 1 个月）
- **年终清算**：12 月底一次扣完：11 月费 + 12 月费 + 年终奖 ≈ **3.5 个月月额**（参数可调）
- **额度管理**：预算授予时全进 IT外包，OD 需要手工调拨（选到预算来源）

### 关键口径

| 指标 | 定义 |
|---|---|
| 执行率 | (IT外包已执行 + OD已执行) ÷ (规划WUSD × 10000 × 当年汇率) |
| 授予进度 | Σ可用预算 ÷ 年初规划 |
| 可支配 | IT外包剩余 + OD剩余（不含 PO 冻结部分） |
| 在途冻结 | OPEN PO 金额 − 已执行部分 |
| 预计返还 | OPEN PO 超出所属月的预测值（验收后回账户） |
| PO 所属月 | 费用起始时间所在月份；超出所属月的预测 = 没花完会返还 |

## 三、数据源与导入

### 平台导出文件（每月 2 次，按年全量）

| 文件 | 内容 | 导入方式 |
|---|---|---|
| PO 明细 ×2（每个花钱项目一份） | PO 编号/金额/状态/月度执行与预测 | 覆盖式刷新 |
| 预算执行表 ×2 | 预算来源 × 费用类型的可用/执行/预测/剩余 | 按日期存快照（累积） |
| 团队 Excel | PO/OD 页签，每行一人（姓名+单价，可选职级列） | 替换式（数据集为准） |

### 导入机制

- **数据集文件夹**：设置一次后，文件丢进去 → 打开看板自动扫描导入
- **文件类型自动识别**：PO明细（含 PO编码 列）、执行表（含 预算来源编码 列）、团队（含 人数+单价 或 姓名+单价 列）
- **快照日期 = 文件导出时间**（不是导入时间）
- **重复文件自动跳过**（按文件名+大小+修改时间）
- **拖拽支持**：可一次拖 4 个文件或整个文件夹

### PO 明细解析要点

- 动态月度列：`N月执行`（过去）/ `N月预测`（当月起），列头随导出月份变化
- **合并单元格兼容**：PO 级列（编号/金额/状态）可能纵向合并，续行为空 → 向下填充
- **金额按 PO 整体只算一次**（同 PO 多行拆分到不同预算来源时）
- **dimension 声明不完整兼容**：部分平台导出只声明到前几行，按实际单元格扩展范围

### 执行表解析要点

- 两级表头：费用类型 → 子列（以前年度/本年度/可用/执行/预测/剩余）
- 自有人力列组自动跳过
- 合计行（编码为 `-`）自动跳过
- OD 剩余 = 可用 − 执行（无预测列）
- IT外包 剩余 = 可用 − 执行 − 预测

### 团队 Excel 解析

- 页签名含 PO/OD 判断渠道
- 只读姓名 + 单价两列（可选职级列做组名），其余列忽略
- 同单价自动归组：组名 = 职级（如有）或 单价值
- 团队配置为**只读**（要改人改价 → 改 Excel → 重新导入）

## 四、决策算法（核心）

### 设计原则

- **PO 金额 = 团队需求（固定）**，不是"补达标"——你不可能让团队花超出能力的钱
- **达标是结果，不是驱动力**——预计执行率是自然产出，不反向影响 PO 金额
- **系统给操作指令**，减少用户手动计算和调拨动作
- **集中分配**——一次 PO 尽量只涉及 1~2 个预算来源（好管理）

### 资金池

```
可用资金 = IT外包剩余 + OD剩余
（不含 PO 冻结部分——那部分要等验收后才回来，时效不可控）
```

### Step 1：各来源达标缺口

```
缺口_i = max(0, 规划_i × 目标_i − 已执行_i − 已下PO预测_i)
```

### Step 2：12月 PO 分配

```
总额 = 团队日额 × 12月工作日 × 出勤系数（固定值）

分配：按缺口从大到小排序，集中分
  分配_i = min(缺口_i, IT剩余_i, 剩余总额度)

效果：缺口大的来源先用完 → 自然只涉及少数来源
```

### Step 3：OD 调拨

```
OD清算需求 = 年终奖倍数 × OD月额
OD需调入 = max(清算需求 − OD已有额度, 0)

从12月PO分配后还有剩余的来源调，优先从已达标且剩余多的调
```

### Step 4：1月 PO

```
1月团队需求 = PO日额 × 1月工作日 × 出勤系数

从OD调拨后的剩余出，优先从剩余多的来源出
```

### Step 5：预计执行率（自然结果）

```
执行率_i = (已执行 + PO预测 + 12月PO_i + OD调拨_i) ÷ 规划_i
→ vs 目标_i → ✓达标 或 ✗差多少
```

### 年底特殊逻辑（11-12月）

- **双月决策**：12月PO（冲今年目标）+ 1月PO（保团队不断档）
- **OD 清算规划**：12月31日一次扣完（含年终奖），需要提前确保额度够
- **留钱策略**：部分项目执行不完是**故意的**（留钱给1月PO），不是失败
- **冻结提醒**：催验收释放资金，12月中旬前完成返还

### 预测模型（B主A兜底）

- **有团队配置时**：PO理论 = Σ(人数×日单价) × 工作日 × 出勤系数；OD理论 = Σ(人数×月单价)
- **无团队配置时**：退回历史月均 × 工作日修正
- **校准**：理论 vs 近3月实际偏差 > 10% → 风险区提醒
- **工作日**：内置法定假日表（2026精确+通用推算引擎），任何年份自动计算

## 五、风险与预警

| 级别 | 类型 | 触发条件 |
|---|---|---|
| 🔴 | 达标风险 | 预计年底 < 目标 |
| 🔴 | 两表不符 | PO明细汇总 ≠ 执行表（超过容差） |
| 🔴 | 编码未关联 | 平台出现新预算来源但未关联规划 |
| 🟡 | 授予落后 | 授予进度 < 时间进度 − 10pt |
| 🟡 | 清算月 | 5月/11月，6月/12月OD大额清算将至 |
| 🟡 | 团队校准偏差 | 理论 vs 实际偏差 > 10% |
| 🟡 | OD额度不足 | 某来源OD已执行 > OD可用 |
| 🟡 | 人数待确认 | 超35天未确认团队人数 |
| 🟡 | 数据过期 | 超过设定天数未导入 |
| ℹ️ | 跨年PO | 次年1-3月识别上年12月服务的PO |
| ℹ️ | 落账节奏 | 11-12月提醒12月PO计入下年 |

## 六、特殊处理

### 剔除机制（两级）

| 级别 | 对象 | 影响 | 恢复 |
|---|---|---|---|
| 预算来源级 | 整个预算来源 + 其所有 PO | 执行/可用/剩余全部不计 | 预算来源页恢复 |
| PO级（挂靠） | 特定 PO | 从PO管理剔除，**已执行仍计入执行率** | PO台账恢复 |

### 失效标记

- **场景**：规划了但预算下不来（给不了了）
- **影响**：从执行率分母剔除、不再催BA
- **恢复**：随时可恢复

### 目标设置

| 值 | 含义 |
|---|---|
| 留空 | 继承年度默认目标（如95%） |
| 数字（如92） | 该来源独立目标 |
| 0 | 不考核（无目标线，进度条旁标"不考核"） |

## 七、技术架构

### 持久化（v2 写穿模式）

```
budget.json（仓库 data/ 目录）= 唯一真源
  → 每次变更自动写入（防抖800ms，原子写）
  → 随 git 同步，清浏览器不丢

localStorage = 缓存
  → 断连时兜底，重连自动同步
  → 顶部横幅显示连接状态
```

### 版本迁移

- schemaVersion 逐级自动迁移
- **迁移前自动备份**原始数据到 `budgetDash.autobak`
- v2/v3 旧数据打开时自动升级

### 分享机制（零部署）

```
维护端（双击打开 file://）：
  正常编辑，数据自动写 budget.json

查看端（局域网 http://IP:8734）：
  双击「启动分享.bat」→ PowerShell 静态服务
  同事浏览器打开 → 自动进入只读模式
  刷新即看最新发布的数据
```

- 发布 = 导出 data.json 放服务目录
- 团队单价默认**不包含**在分享数据中（敏感）
- localhost 永远走编辑模式（维护端不会误入分享模式）

### 数据集文件夹

- Chrome File System Access API
- 文件夹句柄存 IndexedDB，Chrome 记住授权
- 打开看板自动扫描新文件并导入

### 局域网共享

- `启动分享.bat` + `server.ps1`（Windows 自带 PowerShell，零安装零管理员）
- 端口 8734，窗口显示分享地址

## 八、历史数据与学习（待实现）

### 设计思路

历史记录**挂在每次导入上**（不是"看页面"的时间点），因为导入=有新数据=有意义的检查点。

### 数据结构

```json
{
  "importLogs": [
    {
      "date": "2026-11-18",
      "type": "exec_po",
      "snapshot": {
        "execRate": 0.65,
        "forecastRate": 0.85,
        "decPO": 58000,
        "odXfer": 20000,
        "janPO": 55000,
        "sources": { "111": { "rate": 0.80, "gap": 20000 } }
      }
    }
  ]
}
```

### 对比展示

月底导入实际数据后，自动对比上次决策建议 vs 实际结果：

```
上次建议（11-18）vs 实际（11-30）：
  PO 建议 58,000 → 实际 56,500（偏差 -2.6%）
  OD 建议 20,000 → 实际 21,000（偏差 +5.0%）
  执行率预测 85% → 实际 83%（差 2pt）
```

### 长期价值

1. 用户能看到"上个月建议准不准"
2. 系统积累数据后可自动校准出勤系数、年终奖倍数
3. 年底复盘有据可查

## 附录A：汇率与单位

- 规划金额单位：**WUSD（万美金）**，保留小数（如 5.5）
- 平台导出金额单位：**CNY（人民币）**
- 汇率：年度参数，默认 7.03（可调）
- 折算：规划 CNY = WUSD × 10000 × 汇率

## 附录B：中国法定假日

- 精确表：已发布官方安排的年份（含调休），如 2026
- 推算引擎：固定节日（元旦/劳动/国庆）+ 清明节气公式 + 春节/端午/中秋农历表（至2035）
- 未收录年份：退化为固定节日 + 周末法
- 误差：国务院调休拼假不可预知，年误差约 2~4 天（预测用途可忽略）
