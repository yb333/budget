# 📊 年度预算执行看板

单文件网页看板（`index.html`），用 Chrome 双击打开即用，跨年可持续，历史年度随时回看。按真实业务模型构建：**花钱项目 → 预算来源（考核维度）→ 费用类型（IT外包 = PO、人力外包 = OD）**。

打开先看首页：最上面一块**本期结论**先告诉你有没有事；往下是这个月要做什么、执行率到哪了、哪里有问题。完整设计见 [`docs/项目设计文档.md`](docs/项目设计文档.md)。

## 1. 第一次用（四步）

1. **录年初规划**：数据管理 → 年初规划 →「批量粘贴」（每行 `名称, 金额`，金额单位是万美金）或一条条「新增」。平台上出现预算项以后，在每行的「IT 预算项」里选这条规划挂在哪一项
2. **团队 Excel 放进数据集文件夹的根目录**：PO、OD 各一个页签，每人一行（姓名 + 单价）。不配也能用；配上以后预测按人数 × 单价算，更准（见第 6 节）
3. **建数据集文件夹**：每个花钱项目一个子文件夹，把平台导出的文件放进去；数据管理 → 数据与文件 →「设置数据集文件夹」，选它一次。以后打开看板自动导入
4. **选一次数据文件**：数据与文件 →「选择数据文件」，选仓库里的 `data/budget.json`。此后每次改动自动写入，清浏览器也不丢

挂载是**规划 → IT 预算项**（多条规划可以挂同一个）。第一次导入平台数据后，首页待办「N 条规划还没挂 IT 预算项」→ 点了跳到年初规划表，每行的「IT 预算项」下拉里选（显示系统名），选完自动保存，跨年沿用。平台上出现了规划里没有的 IT 预算项时，待办「平台上 N 个 IT 预算项规划里没有」→ 在预算来源页那一行「＋ 新增规划」（IT 预算项自动带上），不是你的就「剔除」。

## 2. 每月怎么用

| 时点 | 做什么 |
|---|---|
| **18~19 号** | 平台导出文件放进数据集文件夹 → 打开看板自动导入 → 看首页的**本期待办**和**本周期操作** |
| **20 号左右** | 按首页的比例表下下月 PO；要调 OD 的，按 OD 那张表调拨 |
| **月底 / 次月初** | 再导一次 → 对账、执行率定格、趋势存档；首页「建议 vs 实际」自动回测上次的估计 |
| **5 月中 / 11 月中** | 清算月：6 月（上半年清算）、12 月（全年 + 年终奖，年终奖月数在参数里校准） |
| **12 月下旬** | 按首页下 1 月 PO（用今年的结余）；12 月 15 日前催完验收，返还的钱才用得上 |
| **规划下来后** | 数据管理 → 数据与文件 →「开启 下一年度」→ 核对金额和汇率 → 正常导入（见第 5 节） |

节奏自己掌握，唯一的硬要求是**下 PO 前有一次导入**。验收哪天到账、哪笔预算什么时候到都不用盯着，下次导入会自动认出来。

### 数据集文件夹

```
数据集/                       ← 设置一次
├── 花钱项目A/                ← 名字自己起，定后不改
│   ├── 项目总览….xlsx        ← 执行表
│   ├── PO明细….xlsx
│   └── 预算授予….xlsx
├── 花钱项目B/
│   └── …
└── 团队.xlsx                 ← 和项目无关的文件放根目录
```

- **项目归属 = 文件所在的子文件夹**。执行表和预算授予没有项目列，必须放进项目子文件夹，否则不导入。以后多一个花钱项目就多建一个文件夹
- 旧文件删不删都行，重复的自动跳过；打开看板自动扫描
- **同一个文件夹里留着新旧几份时，以最新修改的那份为准**：PO 明细每个项目取一份，只替换这个项目的行；团队配置取最新的一份
- **预算授予文件**（平台导出的授予流水）：到账、调拨、往年结转都从这里认出来
- 两个项目的导出文件名相同，挪文件时容易放反。系统会和上次的来源清单比对，**明显像另一个项目时提示「疑似放反」**（只提醒、不拦截），把文件挪到对的文件夹后重新导入即可
- 临时手动导入：顶上「导入平台数据」，拖整个文件夹会按子文件夹识别花钱项目；拖散文件时，执行表和预算授予要在旁边填一下项目名
- **看板更新后不用手动重导**：看板记着每类文件的解析版本，更新后打开时发现版本落后，会自动把数据集里这一类文件重读一遍。如果浏览器这时没有文件夹的读取权限，首页待办里会有「重读 …」，文件不用重新导出。想手动来一遍：数据管理 → 数据与文件 → 解析规则那一行的「全部重读一遍」

### 首页怎么读

从上到下：

- **本期结论**（第一块）：以现在的时间节点回答三件事——有没有执行率风险、有没有钱不够的风险、照着这个月的安排做是不是就没事。一行总结，加三行：执行率、钱、要你处理（只列看板替你解决不了的事，比如催 BA、催验收、再挂 OD、调目标）。结论分三级：照做就没事 / 照做再把下面的事处理掉就没事 / 照做也不行
- **顶部一行**：数据截至哪天；本次导入相比上次发现了什么（新下 PO、验收关闭、OD 扣减、预算到账、调拨、往年结转），明细点开才显示
- **本期待办**：有明确动作的事，每条一行——什么时候、做什么、多少钱。「明细 ↓」跳到对应的那张表；「完成」可以勾，当月有效。鼠标停在条目上能看到说明
- **执行率**：现在 → 目标 → 预计年底，一根刻度条看进度；下面是可支配、在途冻结、到账进度。预计年底的颜色看各考核来源：都达标是绿的，有到不了目标的是红的。按你配置里的安排算（团队 Excel + 变动计划），没配置的 OD 不会替你假设
- **需要留意**：不用去操作系统、但要知道的（钱够不够、年终清算要不要等 11 月 PO 的钱、当月 PO 多下了多少、两表对不对得上、团队配置和实际偏了多少……）
- **本周期操作**：顶上一行**年底预演**（年中起：按现在的安排推到 12 月 31 日会是什么样）；下面是下 PO 的比例表（第 3 节）；再往下折着 OD 怎么挂、钱够不够（按到账时间逐笔看）、年底资金安排、分来源推演表，标题上写着结论
- **来源健康度**：一个 IT 预算项一行，有问题的排在前面。主列是**目标 → 预计年底**——系统的所有决策都是为了这个。状态看年底：`到不了目标`（差多少，以及差的钱是哪种：还没到账 / 还在这一项里只能靠 OD 花 / 钱都到了也不够）、`差一点 · 钱还在`（差的钱都在这个 IT 预算项里，再挂 OD 就能补平）、`规划里没有`（平台有、规划里没对上——新增一条规划挂上，或剔除）、`还没到账`（规划了、平台上还没出现）；达标和不考核的折在下面。条画两根：上面是执行（已执行 → 在途将执行 → 已安排到年底，绿线是目标），下面是到账。一对一的行用规划名当名字（点一下跳到年初规划表改）；多条规划挂同一个 IT 预算项时用系统名，下面每条规划一行
- 最后是折起来的逐月消耗与累计执行率、数据校验（有不符时才出现）、建议 vs 实际

## 3. 下 PO：照着表填

首页 → 本周期操作 →「① 20 号前下 X 月 PO」。每张 PO 一张表，和在系统里填的顺序一样：

- 先按**花钱项目**分（占这张 PO 多少），每个项目内再按**预算项**分（占该项目多少）
- 预算项用的是 **IT 系统里的名字**，在系统里能直接对上。只有看执行率的地方才用年初规划里的名字，并同时标出「系统：xxx」
- 标了〔先把 ¥X 的 OD 额度调回 IT外包〕的，下这张 PO 前先在平台上调
- 标了〔同时出现在两张 PO〕的，是这个预算项的钱被拆到了两张 PO 上。系统尽量不让同一个预算项拆开，只差一点零头时不拆
- 金额的来由写在表上面：**（日额 × 工作日 ＋ 上线周加班）× 出勤系数 = 消耗，加安全垫 = 建议金额**
  - 加班：上线周周末加一天，按 1 倍单价计入当月（2 月、6 月没有上线，就没有）
  - 出勤系数自动从实际反推，平月和「春节当月、1 月」各记各的——调休到次年 1 月作废，大家集中在过年前后休，不能拿年底的出勤去估开春
  - 安全垫是半天日额（出勤系数还是参数里的默认值时是一天）。年底也留：年底缺钱最难受，多下的部分 1 月验收后就退回
  - 实际数和理论差得太离谱时（多半是 PO 明细没导全），不会照着少下：出勤暂用参数里的值，首页报红让你先核对数据
  - **PO 金额 = 团队消耗 + 安全垫**，不按达标缺口反推；达标是推演出来的结果
- 「已下」是哪几张 PO 列在表上面。服务期覆盖下月、已经提前下的 PO 会从这次的金额里扣掉；不属于团队月度消耗的（挂靠、别的用途），点旁边的「剔除出决策」

团队 Excel 里没标「PO归属」时只有一张表；标了会按人员归属分成几张（第 6 节）。

**OD 怎么挂**（②，默认折着，标题写着结论）：

- 每个月底的扣减挂在哪个花钱项目、从哪些预算项出，是**系统替你决定的**，不用先填配置。表里一个月一行；想试别的项目可以在表下面改
- 顺序就是优先级：**先花还有缺口的预算来源**（缺口大的优先），缺口都补到了才花别的来源。年终清算那笔先用验收返还（往月 PO 冻结的钱，12 月 15 日前到账）——这笔钱只有 OD 这一条路能算到今年的执行率；再用已有的 OD 额度；再从 IT外包 调拨；最后才用 11 月 PO 多下的那部分（12 月下旬才到，用了会提醒"时间很紧"）
- 这个月那笔是必做的：够用就是「不用调」；不够给调拨金额、从哪几个预算项调；没有钱可调时明确报「缺 ¥X，没有钱扣」
- **执行率优先于"只挂一个项目"**：有缺口的来源的钱在另一个项目里时，那部分就挂到那个项目上，待办里会有一条「OD 要挂到两个项目」并说明原因
- 返还的钱要到账之后才能转到 OD。所以「往后要转多少」分成现在能调的、和等返还到账后再调的（几号到）

**催 BA**：只管"规划了、还没到账"的钱。已到账 = 往年结转 + 本年度授予；未到账 = 规划金额 − 已到账，平时显示在年初规划表和预算来源页上。待办「催 BA 到账」只在两种情况下出现：到账进度比时间进度落后 10 个百分点以上；或按到账时间排，两个月内手里的钱就不够。PO 冻结的钱是已经到账的，归「催验收」，两者分开提示。

## 4. 其他页签

### 预算来源

- 顶部一行汇总：各类状态几个、总体执行率、规划 / 已到账 / 已执行 / 可支配
- **来源健康度**（整张展开）：规划金额、到账（含往年结转、冻在 PO 里的、未到账）、目标 → 预计年底、执行和到账（两根细条）、已执行、可支配。多条规划挂同一个 IT 预算项时，这个 IT 预算项一行看执行，下面每条规划一行看到账——执行不按规划拆，钱是从 IT 预算项出的
- **钱包**（花钱项目 × 预算项）：到账、已执行、现在剩余、在途冻结、已安排到年底，按花钱项目小计。下 PO 和 OD 扣减都落在钱包上；一个预算项在两个花钱项目下都有钱时，是两个钱包
- 平台上出现了不在你规划里的预算来源，在这一行点「剔除」

### PO 台账

一张 PO 一行（一张 PO 可以跨多个花钱项目、预算项），列出它在每个钱包**冻结多少、验收后返还多少、回到哪个钱包**。

- PO 的服务期按费用**起止时间**判断（覆盖不足 10 天的月份不算，所以 10-31 ~ 11-30 的 PO 是 11 月的）。往月未关闭的，剩余的钱验收后全部退回它当初分配的预算项；当月在执行的，按团队当月需求估会执行多少、多下多少
- 标了「结束时间未读到」的，是导入时没读到费用结束时间，服务期按这张 PO 的月度金额推断
- **在途与返还**：按钱包看冻结和返还
- **多下率**：往月下了多少 vs 实际执行。连续偏大说明习惯性多下
- **剔除出决策**：有的 PO 花的是你的预算，但不是你的 PO 团队在花（挂靠的 PO、别的团队的专项 PO）。不处理的话，系统会把它当成下月「已下」的 PO、分走当月团队需求，它的执行额还会把出勤系数顶高。点 PO 行尾的「剔除出决策」，或首页比例表上面「已下」旁边的那张 PO。之后它不抵下月要下的 PO；它已经执行的、以及今年还会花掉的，仍然计入执行率和对应预算来源的年底执行
- 钱只会退回 PO 当初分配的预算项。能改的是某张 PO 在各预算项上的分配比例，而且要在验收前改。看板不把它作为建议，台账里列了每张 PO 各预算项的冻结和返还，需要时自己判断

### 数据管理

从上到下：

- **数据与文件**：数据文件、数据集文件夹、平台数据（各类文件哪天导的）、解析规则，各一行，带状态和操作。下面是备份与迁移、开启下一年度、维护（示例数据、清空）
- **年初规划**：一行一条规划，每一格都能直接改，改完自动保存——名称、**挂在哪个 IT 预算项**（下拉，显示系统名；已经挂着别的规划的会标出来，多条规划可以挂同一个）、所属花钱项目、金额、目标、备注。还没挂的排在最上面。「到账和执行」一栏写这条规划的到账 / 规划、未到账，和它挂的 IT 预算项的执行情况。目标留空 = 用默认目标，填 0 = 不考核
- **团队配置**（只读，来源是团队 Excel）：下面是「PO 团队的月度需求怎么来的」——建议金额怎么组成、出勤系数是从哪几个月反推的（平月一个，春节当月和 1 月一个），下面列出每个用了的月份的满勤消耗、加班、实际、出勤。变动计划折在下面
- **参数**：汇率、默认执行率目标（没单独设目标的来源用它，写着几个在用）、年终奖扣减月数、上线周加班（每场几个人、哪些月没有上线）、平月和过年月份的出勤系数（自动反推不上时才用）、数据更新提醒。改完自动保存；每月工作日折在下面
- **决策设置**：OD 挂在哪个项目（系统选的，可改、可恢复默认）、剔除的预算来源、剔除出决策的 PO，集中在这里看和恢复
- **授予流水**：以平台导出的预算授予文件为准，全部列出。一个预算项对应多条规划时，每一笔可以选「归哪条规划」

### 规划多条对应系统里一个预算项（少量场景）

年初规划表里让几条规划的「IT 预算项」选同一项（多对一）。系统按 IT 预算项算执行：金额相加、目标按金额加权（不考核的按 0 计）；执行率、缺口、钱包都按这个合并项算。到账按规划分开看：数据管理 → 授予流水里给每一笔选归属。

## 5. 年底与跨年

### 年底资金安排（11、12 月）

首页 → 本周期操作 →「③ 年底资金安排」，把从现在到明年 1 月的每一笔钱摆在一起：

- 三个数：达标来源、预计总体执行率、留给 1 月的 PO（能留多少、团队需要多少、缺多少）
- 总账：今年必须花的（12 月 PO ＋ OD）＋ 留给 1 月 ＝ 多少；钱不够会标红，写明哪一笔没有着落
- 按配置还到不了目标的来源单列一行（差多少、钱还在不在来源里），系统不会替你假设还会再挂 OD
- 安排表按钱的优先级一步一行；「按钱包看」列出每个钱包的进出

口径：

- **优先级**：① 执行率（每个考核来源年底达标，要求 100% 的花完）→ ② OD 尽量只挂在一个花钱项目 → ③ 1 月 PO 用达标之后剩下的钱。PO 和 OD 都先花还有缺口的来源
- **留给 1 月的钱 = 各来源达标之后的结余。** 一个来源有 10 万、执行率要求 80%，最多 2 万可以留给 1 月；各来源加起来是理论上限
- **1 月 PO 的优先级最低。** 不够时每调低某个来源的目标 ¥1，可留就多 ¥1（目标由你权衡）
- **OD 不分临时的还是常驻的。** 写进团队 Excel、变动计划的就是谈成了的，照配置扣；没写进去的系统不替你假设。按配置到年底还差的，待办里写"年底还有 ¥X 到不了目标"——钱还在来源里的，给出再挂约几个 OD 能补平；钱不够的：还没到账的催 BA，其余调低目标或再挂 OD
- **冻结的钱按它回来的时间算。** 往月 PO 没花完的 12 月 15 日前返还，年终清算赶得上，是"只能靠 OD 花"的钱；11 月这张 PO 多下的部分 12 月下旬才返还，年终清算用它时间很紧，用了会提醒。首页「钱够不够」按到账时间逐笔列出每笔支出、到账和之后手里剩多少

### 开启新年度与新年测算

新年的规划下来后（一般在 12 月中）：数据管理 → 数据与文件 →「开启 下一年度」。它会复制本年的规划和参数（挂在哪个 IT 预算项沿用，金额再改成新年的）。

明年的首页顶部会出现**新年测算**（导入明年的平台数据后自动消失）：

- 规划合计、按目标要花掉多少、达标后最多能留给后年 1 月多少
- PO、OD 团队全年各要花多少（含年终奖和变动计划），以及一句话结论：还余多少、够再加几个人；或者超了多少、要减几个人
- 留给后年 1 月的钱够不够；不够时，各考核来源的目标合计还要再降多少

跨年口径：11 月 20 日前后下的 12 月 PO 计入今年；12 月下旬用今年结余下的 1 月 PO 计入明年。执行表自带「以前年度授予未结算」，年底结转不用手工处理。预算几月到账不建模：1 月的 PO 用去年的结余下，到看 2 月的 PO 时如果预算还没到账，首页会提醒。

## 6. 团队 Excel

放数据集根目录。PO、OD 各一个页签，每人一行（姓名 + 单价：PO 填日单价，OD 填月单价）。两个可选：

**① PO 归属——把当月的 PO 按人分几张下。** 加一个页签「po归属」，两列：姓名、归属（如 PO甲 / PO乙）。首页会按人员归属给出每张 PO 的金额和比例表；没填归属的人并成一张。

**② 变动计划——进人、挂人、离场都写在这里。** 加一个页签「变动计划」（页签名含"变动"或"计划"）：

| 生效年月 | 结束年月 | 类型 | 单价 | 人数 | 归属 | 备注 |
|---|---|---|---|---|---|---|
| 2026-10 | 2027-01 | OD | 10500 | +1 |  | 10 月来的临时，干到 12 月 |
| 2026-11 |  | OD | 10500 | +1 |  | 11 月来的常驻 |
| 2026-12 | 2027-01 | OD | 10500 | +3 |  | 12 月来的 3 个临时 |
| 2026-12 | 2027-01 | PO | 2000 | +2 | PO甲 | 12 月临时支援的 PO 人员 |
| 2027-01 |  | PO | 2000 | +3 |  | 明年 1 月到岗的常驻 |
| 2026-11 |  | PO | 1200 | −1 |  | 10 月底走的初级开发 |

- **PO、OD 页签只写常驻人员**（现在在岗的）。临时人员只写在变动计划里
- **填了结束年月 = 临时人员**：只在这一段里算。结束年月填"不再算的那个月"，干到 12 月就填次年 1 月
- **没填结束年月 = 常驻人员的进出**：生效年月填成本归属月（到岗填到岗的月份，离场填离场后的第一个月）。上个月发生的也记一笔，这样最近一笔 OD 扣减才准
- **归属**（可选，只对 PO）：临时的 PO 人员归哪张 PO；不填并到"未标归属"那张
- **不用管 OD 的扣减滞后**，系统自己处理。上面的例子里，OD 页签常驻 3 人，算出来是：10 月 3 人、11 月 4 人、12 月 7 人、明年 1 月 3 人；11 月底扣的是 10 月的费用，按 3 人算
- 按整月算；漏记了，下次导入后系统用平台实际的扣减额校准

## 7. 口径与算法

```
PO 消耗(月m) = (Σ(PO各组 当月人数 × 日单价) × m 月工作日 + 上线周加班) × 出勤系数     当月人数已计入变动计划
               加班 = 加班人数 × 当月平均日单价 × 1 天（1 倍单价）；除 2 月、6 月外每个月都有
               出勤系数 = 实际执行 ÷ 满勤消耗，从已记全的月份反推：平月取最近 3 个，春节当月和 1 月取最近一个有数据的年份
               （离 1 太远的不采用，退回参数里的值）；没有团队配置时退回历史月均 × 工作日修正
建议金额     = 消耗 + 安全垫（半天日额；出勤系数是参数里的值时一天）− 已下
OD 扣减     = 按「费用所属月」的人数 × 月单价；1 月无扣减，2–5 月各扣上月，6 月底扣 5+6 月，7–11 月各扣上月，
              12 月 31 日扣 11 月 + 12 月 + 年终奖（≈3.5 个月，参数）
执行率      = (IT外包已执行 + OD 已执行，截至上月) ÷ (当年规划 × 当年汇率)       按预算来源考核，跨花钱项目合并
总体目标    = 各来源目标 × 规划金额 的加权值（不考核的按 0 计）
来源缺口    = 规划 × 目标 − 已执行 − 在途将执行
可支配      = 各钱包的 IT外包 剩余 + OD 剩余（执行表「剩余」已扣掉平台预测的在途部分）
在途冻结    = PO 总额 − 该 PO 全部行的已执行；验收后返还 = 冻结 − 会执行掉的部分
零头        = 规划的 0.5% 以内且不超过 ¥3,000，不算缺口
已到账      = 往年结转 + 本年度授予（执行表的「可用预算」就是这两列相加），按规划看
未到账      = 规划金额 − 已到账；到账进度落后时间进度 10 个百分点以上、或两个月内手里的钱不够时，出「催 BA 到账」待办
挂载        = 规划 → IT 预算项（多条规划可以挂同一个）；只在年初规划表的下拉里改
年底达标    = 年底预计执行 ≥ 规划 × 目标 − 零头；按配置里的安排算（团队 Excel + 变动计划），没配置的 OD 不假设
花钱顺序    = ① 有缺口的来源（缺口大的优先）→ ② 别的来源；每次先花只有 OD 这一条路的钱（验收返还），再花可支配的钱
钱够不够    = 按到账时间逐笔排：可支配 → 每月 20 号前后的 PO → 月底的 OD → 返还到账；在途冻结按它回来的时间算
工作日      ：内置官方假日表（2026、2027 精确含调休），其他年份自动推算
```

- 平台上的两个特殊项（「不向变更项目申请预算…」「费用先结算至PO受益部门…」）本来就不关联规划，不报未关联
- **OD 当月盲区**：OD 月底扣上月费用、执行表只到上月，看板用团队理论估算，月底导入后校准
- **执行率可能 >100%**：以前年度授予未结算计入可用但不占规划分母，属超额完成
- 每次导入自动记一份建议，下次导入后用实际数回测（首页「建议 vs 实际」）

## 8. 数据存在哪、怎么备份

- **主数据是仓库里的 `data/budget.json`**：选一次文件后每次改动自动写入，随 git 走；浏览器 localStorage 只是缓存。更新 `index.html` 不影响数据
- 顶栏横幅显示文件连没连上。提示「数据文件未连接」时（浏览器更新、权限过期），点顶上「载入数据文件」重连，数据不丢
- **分层备份**（数据管理 → 数据与文件 → 分层备份）：全量（灾备，建议每月）、仅配置（规划 + 团队和变动计划 + 参数 + 决策设置，换电脑、换浏览器时用）、仅数据（快照归档），恢复时自动识别
- 旧版本的数据打开即自动升级，升级前自动备份

## 9. Windows + Chrome

全程不需要敲命令：

1. `git pull` 后，**双击 `index.html`**（用 Chrome 打开）
2. 首次：数据管理 → 数据与文件 →「选择数据文件」→ 选仓库里的 `data/budget.json`（仅此一次，Chrome 会记住；弹出授权点「允许」）
3. 之后每次双击打开自动载入，所有变更（导入、编辑、剔除、换年）自动写入
4. 定期 `git add data/ && git commit && git push`

换电脑：pull 后重复第 2 步。固定用双击打开（不要有时用 localhost 打开），避免数据存成两处。
