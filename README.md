# 📊 年度预算执行看板 v4

单文件预算看板（`index.html`），双击浏览器打开即用，**跨年可持续**（2026 用完 2027 接着用，历史年度永久可回看）。按真实业务模型构建：**花钱项目 → 预算来源（考核维度）→ 费用类型（IT外包=PO / 人力外包OD）**。首页按优先级组织：**① 进展 → ② 风险 → Ⓣ 本周期操作与决策 → ③ 行动清单**（上下全宽布局）。完整设计见 [`docs/项目设计文档.md`](docs/项目设计文档.md)。

## 快速开始

```bash
open index.html          # 或双击；主数据存 data/budget.json（选一次后自动写入），浏览器仅作缓存，无数据库/服务端
```

## 跨年机制（可持续使用）

- **顶栏 ◀ 年度 ▶ 切换器**：随时翻看任意历史年度的定格视图
- **按年分卷**：规划、年度参数（汇率/目标/年终奖/出勤/工作日）每年独立；执行快照/授予流水按日期自然分年；团队配置跨年共用
- **🚀 开启新年**（12月底/1月初，切换到新年一键完成）：复制上年规划（**编码关联自动沿用**，金额可再调）+ 年度参数；平台新出现的编码仍走关联流程
- **跨年执行口径**：11 月 20 日前后下的 12 月 PO 是 12 月的服务，计入今年；12 月下旬用今年结余下的 1 月 PO 是 1 月的服务，计入明年（不算今年执行率）。12 月的决策卡就是这张 1 月 PO 的指令
- **年底结转无需手工处理**：执行表自带「以前年度授予未结算」，新年首次导入自动生效

## 每月例行流程（2 次导入）

| 时点 | 动作 |
|---|---|
| **18~19 号** | 平台导出文件放进数据集文件夹（每个花钱项目的「项目总览」+「PO 明细」）→ 打开看板自动导入 → 看「现在与行动」首页的 **Ⓣ 本周期操作与决策** |
| **20 号左右** | 按决策卡下下月 PO（合计多少、从哪些钱包出）、执行 OD 调拨（卡片会写明在哪个花钱项目内、从哪个来源调） |
| **月底/次月初** | 再导一次 → 对账、执行率定格、月度趋势存档；首页「建议 vs 实际」自动回测上次的估计 |
| **5 月中 / 11 月中** | 清算月预警：6 月（上半年清算）/ 12 月（全年+年终奖，倍数参数可校准） |
| **12 月下旬** | 按 12 月的决策卡下 1 月 PO（用今年结余）；12 月 15 日前催完验收，返还的钱才能用上 |
| **12 月底或 1 月初** | 顶栏切到新年 → 🚀 开启新年 → 核对规划金额与汇率 → 正常导入 |

## 数据集文件夹：每个花钱项目一个子文件夹

```
数据集/                       ← 设置一次
├── 花钱项目A/                ← 名字自己起，定后不改
│   ├── 项目总览….xlsx
│   └── PO明细….xlsx
├── 花钱项目B/
│   ├── 项目总览….xlsx
│   └── PO明细….xlsx
└── 团队.xlsx                 ← 和项目无关的文件放根目录
```

- **项目归属 = 文件所在的子文件夹**。执行表没有项目列，必须放进项目子文件夹，否则不导入（会提示）。以后多一个项目就多建一个文件夹
- 每个项目的两份材料放同一个文件夹；旧文件删不删都行，重复的自动跳过；打开看板自动扫描
- 两个项目的导出文件名相同，从浏览器下载目录挪文件时容易放反。系统会拿新文件和上次的来源清单比对，**明显像另一个项目时提示「疑似放反」**（只提醒，不拦截）；把文件挪到另一个文件夹后重新导入即可覆盖
- 手动拖拽导入（顶部「导入平台数据」）可用：拖整个文件夹会按子文件夹识别项目；拖散文件时在执行表旁填一下项目名

## 决策卡怎么读

卡片最上面是**这个月要做的事**，按顺序：

1. **下 PO**：合计金额 = 团队日额 × 下月工作日 × 出勤系数 × 校准系数（近 3 个月「实际执行 ÷ 理论」，0.9~1.1，多下成了习惯会自动收紧）。团队 Excel 里给每个人标了「PO归属」的，会直接告诉你分几张下、每张多少、各从哪些钱包出；没标的只给合计和钱包。金额已计入变动计划（卡片上有标注）
2. **OD 调拨**：一次调到下一个清算点（全年约 4 次），只动一个花钱项目。够用就显示「不用调」；钱不够调时明确报「额度不够且无钱可调」
3. **催 BA**：哪个来源缺钱、差多少、只靠 PO 消化最晚几月到账

11、12 月会多出**年底推演**：达标来源数、1 月 PO 够不够、年底要不要临时加 OD、验收后能返还多少。分来源的推演表折叠在卡片底部。

原则：**PO 金额 = 团队需求**，不按达标缺口反推；达标是推演出来的结果。各来源的钱互相隔离，一个钱包 = 一个花钱项目下的一个预算来源。

## 团队 Excel 的两个可选项

**① PO 归属——把当月的 PO 按人分几张下。** 团队 Excel 里加一个页签「po归属」，两列：姓名（PO 团队的人）、归属（两张 PO 的简称）。按姓名对应到 PO 页签。

决策卡会写："按人员归属分 2 张下：PO甲 ¥28.5 万（6 人）← 从哪些钱包出；PO乙 ¥20.9 万（6 人）← …"。没填归属的人并成一张。

**② 变动计划——预计进人 / 挂人。** 团队 Excel 里加一个页签「变动计划」（页签名含"变动"或"计划"即可），六列：

| 生效年月 | 结束年月 | 类型 | 单价 | 人数 | 备注 |
|---|---|---|---|---|---|
| 2026-10 | 2027-01 | OD | 10500 | +1 | 10 月来的临时，干到 12 月 |
| 2026-11 |  | OD | 10500 | +1 | 11 月来的常驻 |
| 2026-12 | 2027-01 | OD | 10500 | +3 | 12 月来的 3 个临时 |
| 2027-01 |  | PO | 2000 | +3 | 明年 1 月到岗 |

规则：

- **PO、OD 页签只写常驻人员**（现在在岗的）。临时人员不写进页签，只写在变动计划里
- **填了结束年月 = 临时人员**：只在这一段里算。结束年月填"不再算的那个月"，干到 12 月就填次年 1 月
- **没填结束年月 = 常驻人员的进出**：生效年月填成本归属月，到岗填到岗的月份，离场填离场后的第一个月。上个月发生的也记一笔，这样最近一笔 OD 扣减才准
- **不用管 OD 的扣减滞后**，系统自己处理。上面这个例子里，OD 页签常驻 3 人，算出来是：10 月 3 人、11 月 4 人、12 月 7 人、明年 1 月 3 人；11 月底扣的是 10 月的费用，按 3 人算
- 按整月算；漏记了，下次导入后系统用平台实际的扣减额校准
- 数据管理页能看到计划和各月人数；决策卡上会标注"已计入变动计划"

## PO 台账：在途与返还

PO 台账页一张 PO 一行（一张 PO 可以跨多个花钱项目、多个预算来源），下面列出它在每个钱包**冻结多少、验收后返还多少、回到哪个钱包**。PO 金额按 PO 只算一次，月度执行/预测按行相加。旁边的「多下率」表显示往月下了多少 vs 实际执行，用来控制别下太多。

PO 的三种状态：已关闭的执行额是定稿；**往月未关闭**的，执行额同样不能改，能改的只是下单时各预算项的分配比例——也就是没花完的钱验收后退回到哪个钱包；当月及以后的只有预测，按团队配置估算执行了多少。

改分配比例属于执行中尽量避免的调整，所以看板只在一种情况下把它列为**可选项**：某个预算项缺钱，而同一个 PO 里另一行的返还款用不上。这时决策卡会提示"把某张 PO 的返还 ¥X 改到某个预算项"，PO 台账对应行也会标注。

## 首次使用四步

1. **录规划**（数据管理 → 年初规划）：名称 + 美金金额（编码留空）
2. **团队 Excel 放进数据集文件夹根目录**：PO、OD 各一个页签，每人一行（姓名 + 单价），改完存盘自动生效；需要的话再加「PO归属」列和「变动计划」页签（见下文）
3. **建项目子文件夹、放导出文件**：每个花钱项目一个子文件夹，里面放该项目的「项目总览」和「PO 明细」；打开看板自动导入
4. **编码关联**（预算来源 → 🔗 编码关联）：平台新编码关联到规划项，一次生效，跨年沿用

## 预测模型（团队需求 = 理论 × 校准系数）

```
PO 需求(月m) = Σ(PO各组 当月人数×日单价) × m月工作日 × 出勤系数 × 校准系数     当月人数已计入变动计划
               校准系数 = 近 3 个实际月「实际执行 ÷ 理论」，限制 0.9~1.1；没有团队配置时退回历史月均×工作日修正
OD 扣减     = 按「费用所属月」的人数×月单价；扣减日历：1 月无扣减，2–5 月各扣上月，6 月底扣 5+6 月，7–11 月各扣上月，12 月 31 日扣 11 月 + 12 月 + 年终奖（≈3.5 个月，参数）
              例：11 月底扣的是 10 月的人数×单价，11 月新挂的人不含在内
在途 PO     = 当月在执行的按团队需求拆成「将执行 / 多下」；往月 PO 剩余的全部算验收后返还
校准提醒    ：理论 vs 近 3 月实际偏差 > 10% → 风险区提醒（查人数/单价/出勤）
工作日      ：内置官方假日表（2026、2027 精确含调休），其他年份自动推算
```

## 核心口径

```
执行率   = (IT外包已执行 + OD已执行，截至上月) ÷ (当年规划USD × 当年汇率)      按预算来源考核，跨花钱项目合并
总体目标 = 各来源目标 × 规划金额 的加权值（不考核的按 0 计）
授予进度 = Σ可用预算 ÷ 当年规划   ←落后时间进度10pt预警（催BA依据）
可支配   = 各钱包的 IT外包剩余 + OD剩余（执行表「剩余」已扣全部在途 PO 预测，不含冻结）
在途冻结 = PO 总额 − 该 PO 全部行的已执行；验收后返还 = 冻结 − 会执行掉的部分
来源缺口 = 规划×目标 − 已执行 − 在途将执行

## 数据安全（逻辑与数据分离）

- **主数据存仓库里的 `data/budget.json`**（选一次文件后每次变更自动写入，见下文），浏览器 localStorage 只是缓存；更新 index.html 文件不影响数据
- **schemaVersion 版本迁移链**（v2 → v3 → v4）：看板逻辑升级时旧数据自动逐级迁移；迁移前自动备份到独立存储键（budgetDash.backup.* / budgetDash.autobak），杜绝"升级后数据没了"
- v4 新增：执行表按花钱项目分存、导入记录与回测。v3 及更早的数据打开即自动升级；旧快照保留合并视图，把执行表放进项目子文件夹重新导入后，决策建议就能区分花钱项目
- **分层备份**（数据管理 → 分层备份）：全量（灾备，建议每月）/ 仅配置（规划+团队+参数，换环境迁移）/ 仅数据（快照归档），恢复自动识别

## 重要说明

- **OD 当月盲区**：OD 月底扣上月费用、执行表只到上月——看板用月均/团队理论估算并标注，月底导入后校准
- **执行率可能 >100%**：以前年度授予未结算计入可用但不占规划分母，属超额完成
- **PO 返还**：OPEN PO 超出执行窗口的预测 ≈ 验收后返还（周期约 1 个月，首页提醒催验收）

## 无脑操作指南（Windows + Chrome）

**持久化架构（v2 写穿）**：`budget.json` = 唯一真源——**选一次文件后，每次变更自动写入**（随 git 同步，清浏览器不丢）；浏览器 localStorage 只是缓存兜底，文件断连时数据暂存缓存、重连自动同步，顶部横幅实时显示连接状态。

**自己用（维护端）——全程不需要任何命令：**

1. `git pull` 后，**双击 `index.html`**（用 Chrome 打开）
2. 首次：数据管理 → **💾 保存到数据文件** → 选仓库里的 `data/budget.json`（仅此一次，Chrome 记住）
3. 之后每次双击打开自动载入，**所有变更（导入/编辑/剔除/换年）实时写入 budget.json**——无需任何手动保存
4. 定期 `git add data/ && git commit && git push`（用你顺手的 git 工具）

> Chrome 首次授权文件访问点「允许」。换电脑：pull 后重复第 2 步。若横幅提示"数据文件未连接"（浏览器更新/权限过期），点顶部「📂 载入数据文件」重连一次即恢复。

**给同事看（分享端）——双击启动：**

1. 先在维护端点 **📤 发布分享** 生成 `data.json`，放到仓库根目录（index.html 旁边）
2. **双击 `启动分享.bat`**——窗口会显示分享地址 `http://你的IP:8734/`（首次弹防火墙选「允许访问」）
3. 把地址发给同事，浏览器打开即看（只读模式，刷新即最新）
4. 关闭那个黑窗口 = 停止分享

> `启动分享.bat` 调用同目录 `server.ps1`（Windows 自带 PowerShell，零安装、无需管理员权限）。如果你本来就有内网 Web 服务，把 index.html + data.json 放进去也一样。

## 开发环境 ↔ 内网机器同步（git 工作流）

主数据落盘为仓库里的 **`data/budget.json`**，随 git 走（Windows 无脑流程见上一节；Mac/Linux 起服务可用 `python3 -m http.server 8734`）。

- Chrome/Edge 支持直接写回文件；Safari 会退化为下载 budget.json 手动覆盖到 data/
- 浏览器 localStorage 始终双写（日常打开免手动加载，budget.json 是同步/备份载体）
- **换电脑/换浏览器**：pull 后「📂 打开」budget.json 即接管
- 敏感提示：budget.json 含规划金额与团队单价，不想进公司远端就把 `.gitignore` 里那行注释解开

## 每月导入：放进项目子文件夹（或拖拽）

日常靠数据集文件夹自动导入（结构见上文）。临时手动导入：顶部「导入平台数据」，拖整个文件夹会按子文件夹识别花钱项目；拖散文件时在执行表旁填项目名（执行表必须带项目，否则不导入）。

**无需前后端、无需数据库**——同一份 index.html 两种角色：

- **你（维护端）**：双击打开，正常编辑；点「数据管理 → 📤 发布分享」生成 `data.json`
- **同事（只读端）**：你本机跑 `python3 -m http.server 8734`（目录里放着 index.html + data.json），同事访问 `http://你的IP:8734`——页面检测到 data.json 自动进入**分享只读模式**：横幅标注数据截至时间，所有编辑按钮与数据管理页隐藏，刷新即看你最新发布的内容

发布选项：包含 PO 明细（默认开）、包含团队配置（人数单价敏感，默认**不**包含）。主数据永远只在你浏览器里，发什么、何时发由你决定。

> BA 关注的问题在只读端直接可查：账户水位（首页「可用/剩余」）、哪个该申请（预算来源表的授予进度与「催 BA」预警）、到账情况（授予流水 + 执行表授予列交叉校验）。

注意：localhost 与双击打开是两个独立存储——你（维护端）固定用双击打开，避免数据存两处。
