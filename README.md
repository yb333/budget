# 📊 年度预算执行看板 v3

单文件预算看板（`index.html`），双击浏览器打开即用，**跨年可持续**（2026 用完 2027 接着用，历史年度永久可回看）。按真实业务模型构建：**预算来源（考核维度）→ 花钱项目 → 费用类型（IT外包=PO / 人力外包OD）**。首页按优先级组织：**① 进展 → ② 风险 → ③ 本周期行动清单**（上下全宽布局）。

## 快速开始

```bash
open index.html          # 或双击；数据存本浏览器 localStorage，无任何数据库/服务端
```

## 跨年机制（可持续使用）

- **顶栏 ◀ 年度 ▶ 切换器**：随时翻看任意历史年度的定格视图
- **按年分卷**：规划、年度参数（汇率/目标/年终奖/出勤/工作日）每年独立；执行快照/授予流水按日期自然分年；团队配置跨年共用
- **🚀 开启新年**（12月底/1月初，切换到新年一键完成）：复制上年规划（**编码关联自动沿用**，金额可再调）+ 年度参数；平台新出现的编码仍走关联流程
- **跨年执行口径**（12月服务→次年1月下PO→计入次年执行）：次年 1~3 月视图自动识别并标注「跨年 PO ¥X（上年12月服务）」，勿当本年新增消耗追账；11~12 月风险区提醒「冲今年执行率只能靠年内可执行完的 PO + OD 年终清算」
- **年底结转无需手工处理**：执行表自带「以前年度授予未结算」，新年首次导入自动生效

## 每月例行流程（2 次导入）

| 时点 | 动作 |
|---|---|
| **18~19 号** | 平台导出 4 个文件（PO明细×2 + 预算执行×2，按年全量）→ 顶部「📥 导入」→ 看「现在与行动」首页 |
| **20 号左右** | 按行动清单下下月 PO、执行 OD 调拨（IT外包→OD，选到预算来源） |
| **月底/次月初** | 再导一次 → 对账、执行率定格、月度趋势存档 |
| **5 月中 / 11 月中** | 清算月预警：6 月（上半年清算）/ 12 月（全年+年终奖，倍数参数可校准） |
| **12 月底或 1 月初** | 顶栏切到新年 → 🚀 开启新年 → 核对规划金额与汇率 → 正常导入 |

## 首次使用四步

1. **录规划**（数据管理 → 年初规划）：名称 + 美金金额（编码留空）
2. **录团队配置**（数据管理 → 团队配置）：按组建「高级开发×N·日单价¥X」「OD×N·月单价¥Y」；人数变化时更新
3. **导 4 个文件**：自动识别；执行表按快照日期合并，PO明细覆盖刷新
4. **编码关联**（预算来源 → 🔗 编码关联）：平台新编码关联到规划项，一次生效，跨年沿用

## 预测模型（B主A兜底）

```
PO(月m) = max(平台预测m, 团队理论m, 历史月均×工作日修正)   团队理论 = Σ(PO组人数×日单价) × m月工作日 × 出勤系数
OD(月m) = 团队理论(Σ人数×月单价) 或 历史月均；6月×2、12月×年终奖倍数
校准   ：理论 vs 近3月实际偏差>10% → 风险区提醒（查人数/单价/出勤）
工作日 ：默认按周末计算，参数页按国务院放假安排（含调休）微调一次
```

## 核心口径

```
执行率   = (IT外包已执行 + OD已执行，截至上月) ÷ (当年规划USD × 当年汇率)
授予进度 = Σ可用预算 ÷ 当年规划   ←落后时间进度10pt预警（催BA依据）
剩余     = 执行表「剩余」列 = 可支配余额（IT外包已扣PO预测；OD 未扣）
```

## 数据安全（逻辑与数据分离）

- **数据只存浏览器 localStorage**，更新 index.html 文件不影响数据
- **schemaVersion 版本迁移链**：看板逻辑升级时旧数据自动逐级迁移；迁移前自动备份到独立存储键（budgetDash.backup.*），杜绝"升级后数据没了"
- v2 旧数据/旧备份文件打开或导入时自动升级接管
- **分层备份**（数据管理 → 分层备份）：全量（灾备，建议每月）/ 仅配置（规划+团队+参数，换环境迁移）/ 仅数据（快照归档），恢复自动识别

## 重要说明

- **OD 当月盲区**：OD 月底扣上月费用、执行表只到上月——看板用月均/团队理论估算并标注，月底导入后校准
- **执行率可能 >100%**：以前年度授予未结算计入可用但不占规划分母，属超额完成
- **PO 返还**：OPEN PO 超出执行窗口的预测 ≈ 验收后返还（周期约 1 个月，首页提醒催验收）

## 无脑操作指南（Windows + Chrome）

**自己用（维护端）——全程不需要任何命令：**

1. `git pull` 后，**双击 `index.html`**（用 Chrome 打开）
2. 首次：数据管理 → **📂 打开/恢复数据文件** → 选仓库里的 `data/budget.json`（此后 Chrome 记住这个文件）
3. 之后每次双击打开，看板**自动载入** budget.json（无需任何操作）；日常变更自动存浏览器
4. 变更/导入后点一下 **💾 保存到数据文件** → 直接写回 budget.json（同一次打开里再存不用重选文件）
5. `git add data/ && git commit && git push`（用你顺手的 git 工具，SourceTree 也行）

> Chrome 首次载入/保存会弹一次文件访问授权，选「允许」即可。换电脑：pull 后重复第 2 步。

**给同事看（分享端）——双击启动：**

1. 先在维护端点 **📤 发布分享** 生成 `data.json`，放到仓库根目录（index.html 旁边）
2. **双击 `启动分享.bat`**——窗口会显示分享地址 `http://你的IP:8734/`（首次弹防火墙选「允许访问」）
3. 把地址发给同事，浏览器打开即看（只读模式，刷新即最新）
4. 关闭那个黑窗口 = 停止分享

> `启动分享.bat` 调用同目录 `server.ps1`（Windows 自带 PowerShell，零安装、无需管理员权限）。如果你本来就有内网 Web 服务，把 index.html + data.json 放进去也一样。

## 开发环境 ↔ 内网机器同步（git 工作流）

主数据落盘为仓库里的 **`data/budget.json`**，随 git 走（Windows 无脑流程见上一节；Mac/Linux 起服务可用 `python3 -m http.server 8734`）。

- Chrome/Edge 支持直接写回文件；Safari 会退化为下载 budget.json 手动覆盖到 data/
- 浏览器 localStorage 始终双写（日常打开免手动加载，budget.json 是同步/备份载体）
- **换电脑/换浏览器**：pull 后「📂 打开」budget.json 即接管
- 敏感提示：budget.json 含规划金额与团队单价，不想进公司远端就把 `.gitignore` 里那行注释解开

## 每月导入：一次拖 4 个文件

平台导出的 PO明细×2 + 预算执行×2，**全选一次拖入**导入框即可（也支持把 4 个文件放一个文件夹直接拖文件夹）。自动识别类型，无需分 4 次上传。

**无需前后端、无需数据库**——同一份 index.html 两种角色：

- **你（维护端）**：双击打开，正常编辑；点「数据管理 → 📤 发布分享」生成 `data.json`
- **同事（只读端）**：你本机跑 `python3 -m http.server 8734`（目录里放着 index.html + data.json），同事访问 `http://你的IP:8734`——页面检测到 data.json 自动进入**分享只读模式**：横幅标注数据截至时间，所有编辑按钮与数据管理页隐藏，刷新即看你最新发布的内容

发布选项：包含 PO 明细（默认开）、包含团队配置（人数单价敏感，默认**不**包含）。主数据永远只在你浏览器里，发什么、何时发由你决定。

> BA 关注的问题在只读端直接可查：账户水位（首页「可用/剩余」）、哪个该申请（预算来源表的授予进度与「催 BA」预警）、到账情况（授予流水 + 执行表授予列交叉校验）。

注意：localhost 与双击打开是两个独立存储——你（维护端）固定用双击打开，避免数据存两处。
